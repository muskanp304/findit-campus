1. Aim of the Experiment

To design, configure, and implement an end-to-end automated DevOps pipeline for a full-stack mini project (FindIt Campus) using Git, GitHub, GitHub Actions / Jenkins, Docker, and Nginx. The pipeline incorporates version control, static code analysis, automated testing, production build optimization, multi-stage Docker containerization, and automated deployment.

2. Objectives

  • Establish a Git-based version control strategy with branch protection and pull request workflows.
  • Implement automated static code quality analysis and linting gates using oxlint.
  • Implement automated unit and smoke testing using Node.js built-in test runner.
  • Implement an optimized multi-stage Dockerfile converting a React + Vite application into an ultra-lean Nginx container.
  • Automate CI/CD pipelines through GitHub Actions (.github/workflows/ci-cd-pipeline.yml) and Jenkinsfile.
  • Validate containerized deployment and health endpoints via Docker Compose.

5. Core Configuration Files

A. Multi-Stage Dockerfile (Dockerfile):

# Stage 1: Build Environment
FROM node:22-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci || npm install
COPY . .
RUN npm run build

# Stage 2: Production Nginx Runtime
FROM nginx:1.27-alpine AS runner
RUN rm -rf /usr/share/nginx/html/*
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
HEALTHCHECK --interval=30s --timeout=5s --start-period=5s --retries=3 \
  CMD wget --quiet --tries=1 --spider http://127.0.0.1:80/ || exit 1
CMD ["nginx", "-g", "daemon off;"]

B. Nginx Single-Page Application Configuration (nginx.conf):

server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    gzip on;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;

    location ~* \.(?:css|js|jpg|jpeg|png|svg|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, max-age=31536000, immutable";
    }

    # SPA Client-Side Routing Fallback
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Health Check Endpoint
    location /healthz {
        return 200 '{"status":"healthy","service":"findit-campus"}';
        add_header Content-Type application/json;
    }
}

8. Viva Voce Questions & Answers

Q1: Why is multi-stage Docker build superior to a single-stage build for web apps? Single-stage builds bundle Node.js runtimes, package managers, and large node_modules (often >800MB). Multi-stage builds compile assets in Stage 1 and discard the compiler, copying only static HTML/JS into a ~23MB Nginx Alpine container, dramatically improving speed, memory efficiency, and security.
Q2: Why is the try_files $uri $uri/ /index.html; directive essential in Nginx? React utilizes client-side history API routing. When a user directly visits a path like /dashboard, Nginx would normally return a 404 since no physical folder exists. try_files directs Nginx to serve index.html as fallback, allowing React's router to render the correct view.
Q3: What role does a CI pipeline play before merging pull requests? Continuous Integration executes automated linting and unit tests on every pull request. If tests or builds fail, the PR is automatically blocked from merging into main, preventing defects from reaching production.
